# 7.4 面番号変更（保存データ有無で分岐）

## 概要
TGまたはボタン操作による面番号変更要求を受け、FRAM内の重複チェック後にSETAXONコマンドで新FACE番号をAXONに書き込む。既存の金額設定とカウンタは引き継ぐ。

## 使用コマンド

### SOMA → AXON
- **SETAXON (0x4A)**: 新FACE番号書き込み
  - SET_FACE_N: 新FACE番号
  - SET_CASH_VLU: 既存金額（引継ぎ）
  - SET_TOUT: 既存タイムアウト（引継ぎ）

### AXON → SOMA
- **ACK (0x00)**: 設定受信確認

### 3. SETAXON書き込み ✅
- [x] SETAXON で新 FACE を書き込み
- [x] 36バイトフレーム構築
  - Header: 0x14
  - Length: 0x20
  - Command: 0x4A (SETAXON)
  - Data[0]: FACE_N (new_face)
  - Data[1]: SET_SOL (0x00)
  - Data[2]: SET_LED (0x00)
  - Data[3]: SET_TOUT (old_entry.timeout)
  - Data[6]: SET_FACE_N (new_face)
  - Data[7-8]: SET_CASH_VLU (old_entry.cash_value)
  - CRC16: 計算値
- [x] MUX切替
- [x] UART送信

### 4. ACK確認 ✅

- [ ] **FRAM の FACE 番号・金額を更新（引継ぎ処理含む）**

  new_entry.port_num = port;

## エラーケース

| エラー | 原因 | 対処 |
|-------|------|------|
| 重複エラー | FACE番号が既に使用中 | NACK返送、変更中止 |
| ACKタイムアウト | AXON応答なし | 3回リトライ後エラー |
| CRCエラー | 通信エラー | 再送 |
| FRAM書込失敗 | FRAMエラー | エラーログ、復旧試行 |

## 備考
- FACE番号0は無効化用（7.5参照）
- 重複チェックは必須（重複禁止）
- カウンタ引継ぎで販売実績を保持
- 変更確定前にバックアップ推奨
- ドア開放中は変更禁止
