## 4. データフロー整合性

### 4.1 現金決済時のLatchクリアフロー

**仕様書記載**（通信シーケンス仕様書 Line 387-395）:
```
SOMA: Latchクリア実行
  - SET_PRTS bit2=1（現金センサークリア）
  - SET_PRTS bit5=1（ダイヤル回転クリア）
  ↓
AXON: [SETAXON]受信
  - STATUS bit3: 1→0（現金センサーリセット）
  - STATUS bit7: 1→0（ダイヤル回転リセット）
```

**実装確認**（s2a_packet.c Line 867-888）:
```c
// bit5: ダイヤル回転検知（Latch）クリア
if (set_prts & S2A_SETAXON_PRTS_DIAL_CLEAR) {
    extern volatile uint8_t g_dial_rotation_count;
    g_dial_rotation_count = 0;  // カウンタリセット
    g_axon_status_shared.dial_rotated = 0;  // Latchクリア
}

// bit2: 現金用 光センサー（Latch）リセット
if (set_prts & S2A_SETAXON_PRTS_COIN_SENSOR_RST) {
    g_axon_status_shared.coin_detected = 0;
}
```

**整合性検証**:
- ✅ bit5受信 → `g_dial_rotation_count = 0` + `dial_rotated = 0`
- ✅ bit2受信 → `coin_detected = 0`
- ✅ 仕様書の「SET_PRTS bit2,5 → STATUS bit3,7クリア」と一致

**結論**: ✅ **Latchクリアフローが仕様書と完全一致**

**整合性検証**:
- ✅ ダイヤル回転 → bit7=1（Latch式）
- ✅ STATUS[15:8]にカウント値を格納
- ✅ 仕様書の「STATUS bit7 + STATUS[15:8]=カウント」と一致
