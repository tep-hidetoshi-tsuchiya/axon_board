## 1. 概要

Ver1.0 から Ver1.2 への変更により、SETAXON, CHKAXON, ATCKSB コマンドの仕様が大幅に拡張されました。

### 変更内容の特徴

- **SETAXON**: SET_FACE ビット定義が拡張（新規機能追加）
- **CHKAXON**: 構造は変わらず
- **ATCKSB**: CHK_FACE ビット定義が大幅に拡張（完全に異なる機能を持つように）

---

## 2. SETAXON コマンド差分

### 2.1 基本フォーマット

✓ **フォーマット構造**: 変更なし

```
両バージョンとも:
Header | LEN | ID | FACE_N | SET_FACE | SET_LED | SET_TOUT | RFU×21 | DIC | AuthCode | RND | CRC16
```

### 2.2 SET_FACE ビット定義の拡張

#### Ver 1.0: SET_FACE 定義

| Bit | 項目 | 説明 |
|-----|------|------|
| 7 | AXON基板リセット命令 | 0: 通常, 1: リセット |
| 6 | RFU | (予約) |
| 5 | RFU | (予約) |
| 4 | 現金ブロックON | 0: OFF, 1: ON |
| 3 | RFU | (予約) |
| 2 | RFU | (予約) |
| 1 | RFU | (予約) |
| 0 | 電子マネー用ソレノイドON | 0: OFF, 1: ON |

**使用中のビット**: 7, 4, 0 (3個)
**予約ビット (RFU)**: 6, 5, 3, 2, 1 (5個)

#### Ver 1.2: SET_FACE 定義

| Bit | 項目 | 説明 |
|-----|------|------|
| 7 | AXON基板リセット命令 | 0: 通常, 1: リセット |
| 6 | RFU | (予約) |
| **5** | **ダイヤル回転検知（Latch）クリア** | **0: 維持, 1: クリア** |
| 4 | 現金ブロックON | 0: OFF, 1: ON |
| **3** | **現金返却ボタン（Latch）リセット** | **0: 維持, 1: クリア** |
| **2** | **現金用 光センサー（Latch）リセット** | **0: 維持, 1: クリア** |
| 1 | RFU | (予約) |
| 0 | RFU | (予約) |

**使用中のビット**: 7, 5, 4, 3, 2 (5個)
**予約ビット (RFU)**: 6, 1, 0 (3個)

#### 差分一覧

| Bit | Ver 1.0 | Ver 1.2 | 変更内容 |
|-----|---------|---------|----------|
| 7 | AXON基板リセット命令 | AXON基板リセット命令 | ✓ 同じ |
| 6 | RFU | RFU | ✓ 同じ |
| 5 | RFU | **ダイヤル回転検知クリア** | **⚠️ 新規機能追加** |
| 4 | 現金ブロックON | 現金ブロックON | ✓ 同じ |
| 3 | RFU | **現金返却ボタンリセット** | **⚠️ 新規機能追加** |
| 2 | RFU | **光センサーリセット** | **⚠️ 新規機能追加** |
| 1 | RFU | RFU | ✓ 同じ |
| 0 | 電子マネー用ソレノイドON | RFU | **⚠️ 機能削除** |

### 2.3 SET_TOUT デフォルト値の確認

✓ **変更なし**

```
Ver 1.0: 0x0 = 60秒 (Default)
Ver 1.2: 0x0 = 60秒 (Default)
```

### 2.4 SET_FACE 差分の影響

#### ✅ 互換性の問題

**⚠️ 重大な非互換性が存在:**

```
Ver1.0 でコード例:
  SET_FACE = 0x01  → Bit 0 = 1 (ソレノイドON)

Ver1.2 では:
  SET_FACE = 0x01  → Bit 0 = RFU (何の意味もない)

結果: 既存コードがそのまま動作しない
```

## 4. ATCKSB コマンド差分

### 4.1 基本フォーマット

✓ **フォーマット構造は同じ（RFUサイズは同じ）**

```
Header | LEN | ID | FACE_N | CHK_FACE | CHK_LED | CHK_TOUT | RFU×21 | DIC | AuthCode | RND | CRC16
```

### 4.2 CHK_FACE ビット定義の大幅拡張

#### Ver 1.0: CHK_FACE 定義

| Bit | 項目 | 説明 |
|-----|------|------|
| 7 | RFU | (予約) |
| 6 | RFU | (予約) |
| 5 | RFU | (予約) |
| 4 | 現金ブロック状態確認 | 0: OFF, 1: ON |
| 3 | RFU | (予約) |
| 2 | RFU | (予約) |
| 1 | RFU | (予約) |
| 0 | 電子マネー用ソレノイド状態確認 | 0: OFF, 1: ON |

**使用中のビット**: 4, 0 (2個)
**予約ビット (RFU)**: 7, 6, 5, 3, 2, 1 (6個)

#### Ver 1.2: CHK_FACE 定義

| Bit | 項目 | 説明 |
|-----|------|------|
| **7** | **ダイヤル回転検知状態** | **0: 通常, 1: 回転検知** |
| **6** | **ドア開閉状態** | **0: 通常, 1: OPEN** |
| **5** | **現金ブロック状態** | **0: 通常, 1: ブロック** |
| **4** | **現金返却ボタン押下検出** | **0: 通常, 1: 押下** |
| **3** | **現釓用 光センサー** | **0: 投入中, 1: なし** |
| **2** | **電子マネー用ソレノイド状態** | **0: 回転不可, 1: 回転OK** |
| **1** | **売り切れ検知状態** | **0: 通常, 1: 売り切れ** |
| **0** | **FACEの有効無効状態** | **0: 無効, 1: 有効** |

**使用中のビット**: 7, 6, 5, 4, 3, 2, 1, 0 (8個)
**予約ビット (RFU)**: なし

#### 差分一覧

| Bit | Ver 1.0 | Ver 1.2 | 変更内容 |
|-----|---------|---------|----------|
| 7 | RFU | **ダイヤル回転検知状態** | **⚠️ 新規機能追加** |
| 6 | RFU | **ドア開閉状態** | **⚠️ 新規機能追加** |
| 5 | RFU | **現金ブロック状態** | **⚠️ 新規機能追加** |
| 4 | 現金ブロック状態確認 | **現金返却ボタン検出** | **⚠️ 意味が完全に変わる** |
| 3 | RFU | **現金用光センサー状態** | **⚠️ 新規機能追加** |
| 2 | RFU | **電子マネー用ソレノイド状態** | **⚠️ 新規機能追加** |
| 1 | RFU | **売り切れ検知状態** | **⚠️ 新規機能追加** |
| 0 | 電子マネー用ソレノイド状態 | **FACE有効無効状態** | **⚠️ 意味が完全に変わる** |

### 4.3 CHK_TOUT デフォルト値の確認

✓ **変更なし**

```
Ver 1.0: 0x0 = 30秒 (Default)
Ver 1.2: 0x0 = 30秒 (Default)
```

### 4.4 CHK_FACE 差分の影響

#### ✅ 互換性の問題

**⚠️ 極めて重大な非互換性が存在:**

```
Ver1.0 デコード例:
  CHK_FACE = 0x01  → Bit 0 = 1 (ソレノイドON)
  CHK_FACE = 0x10  → Bit 4 = 1 (ブロック状態)

Ver1.2 では:
  CHK_FACE = 0x01  → Bit 0 = 1 (FACE有効)
  CHK_FACE = 0x10  → Bit 4 = 1 (返却ボタン押下)

結果: ビット値の意味が完全に逆転
```

## 5. 統合差分サマリー

### 5.1 3コマンドの変更影響比較

| コマンド | Ver1.0 | Ver1.2 | 差分レベル | 互換性 |
|---------|--------|--------|-----------|--------|
| SETAXON | 3機能 | 5機能 | **大幅拡張** | ❌ 非互換 |
| CHKAXON | - | - | **変更なし** | ✅ 互換 |
| ATCKSB | 2機能 | 7機能 | **極度に拡張** | ❌ 非互換 |

### 5.2 機能追加の詳細

#### 表1. SETAXON コマンド - SET_FACE ビット定義の拡張

| Bit | Ver1.0 | Ver1.2 | 変更 |
|-----|--------|--------|------|
| 7 | リセット命令 | リセット命令 | ✓ 同じ |
| 6 | RFU | RFU | ✓ 同じ |
| 5 | RFU | ダイヤルクリア | ⚠️ 新規 |
| 4 | 現金ブロック | 現金ブロック | ✓ 同じ |
| 3 | RFU | ボタンリセット | ⚠️ 新規 |
| 2 | RFU | センサーリセット | ⚠️ 新規 |
| 1 | RFU | RFU | ✓ 同じ |
| 0 | ソレノイドON | RFU | ❌ 削除 |

#### 表2. ATCKSB コマンド - CHK_FACE ビット定義の大幅拡張

| Bit | Ver1.0 | Ver1.2 | 変更度 |
|-----|--------|--------|-------|
| 7 | RFU | ダイヤル回転検知 | ⚠️ 新規 |
| 6 | RFU | ドア開閉状態 | ⚠️ 新規 |
| 5 | RFU | ブロック状態 | ⚠️ 新規 |
| 4 | ブロック状態 | 返却ボタン検出 | ❌ 意味変更 |
| 3 | RFU | 光センサー | ⚠️ 新規 |
| 2 | RFU | ソレノイド状態 | ⚠️ 新規 |
| 1 | RFU | 売り切れ検知 | ⚠️ 新規 |
| 0 | ソレノイド状態 | FACE有効無効 | ❌ 意味変更 |

#### SETAXON に追加された機能 (Ver1.2)

1. **ダイヤル回転検知（Latch）クリア** (Bit 5)
   - Ver1.0: 使用されていなかった
   - Ver1.2: 新規機能

2. **現金返却ボタン（Latch）リセット** (Bit 3)
   - Ver1.0: 使用されていなかった
   - Ver1.2: 新規機能

3. **現金用 光センサー（Latch）リセット** (Bit 2)
   - Ver1.0: 使用されていなかった
   - Ver1.2: 新規機能

#### SETAXON で削除された機能 (Ver1.2)

1. **電子マネー用ソレノイドON** (Bit 0)
   - Ver1.0: Bit 0 = 1 でソレノイドON
   - Ver1.2: Bit 0 は RFU に変更

#### ATCKSB に追加された機能 (Ver1.2)

1. **ダイヤル回転検知状態** (Bit 7)
2. **ドア開閉状態** (Bit 6)
3. **現金ブロック状態** (Bit 5)
4. **売り切れ検知状態** (Bit 3)

#### ATCKSB で意味が変わった機能 (Ver1.2)

| Bit | Ver1.0 項目 | Ver1.2 項目 | 変更 |
|-----|-----------|-----------|------|
| 4 | 現金ブロック状態 | 現金返却ボタン押下検出 | 完全に異なる |
| 0 | ソレノイド状態 | FACE有効無効状態 | 完全に異なる |

## 6. 実装への影響

### 6.1 ⚠️ 緊急対応が必要な項目

#### 【SETAXON実装への影響】

```c
// Ver1.0 コード例 (これは Ver1.2 では動作しません)
void setAxonSolenoid(uint8_t face_n, uint8_t on) {
    uint8_t set_face = 0x00;
    if (on) {
        set_face |= 0x01;  // Bit 0 = 1 (Ver1.0 ではソレノイド)
    }
    // Ver1.2 では Bit 0 は RFU なので効果なし
}

// Ver1.2 対応 (新しい機能を使う場合)
void setAxonFaceControl(uint8_t face_n, uint8_t reset, uint8_t dial_clear, uint8_t block, uint8_t button_reset, uint8_t sensor_reset) {
    uint8_t set_face = 0x00;
    if (reset)        set_face |= 0x80;  // Bit 7
    if (dial_clear)   set_face |= 0x20;  // Bit 5 (新規)
    if (block)        set_face |= 0x10;  // Bit 4
    if (button_reset) set_face |= 0x08;  // Bit 3 (新規)
    if (sensor_reset) set_face |= 0x04;  // Bit 2 (新規)
}
```

#### 【ATCKSB実装への影響】

```c
// Ver1.0 デコード例 (これは Ver1.2 では誤った解釈)
void parseAtcksbVer10(uint8_t chk_face) {
    if (chk_face & 0x10) {  // Bit 4 = 1
        printf("ブロック状態\n");  // Ver1.0 では正しい
    }
    if (chk_face & 0x01) {  // Bit 0 = 1
        printf("ソレノイドON\n");  // Ver1.0 では正しい
    }
}

// Ver1.2 デコード例 (Ver1.0 のコード例は誤った解釈をする)
void parseAtcksbVer12(uint8_t chk_face) {
    if (chk_face & 0x80) printf("ダイヤル回転中\n");        // Bit 7 (新規)
    if (chk_face & 0x40) printf("ドア開放中\n");            // Bit 6 (新規)
    if (chk_face & 0x20) printf("ブロック中\n");            // Bit 5 (新規)
    if (chk_face & 0x10) printf("返却ボタン押下\n");        // Bit 4 (変更)
    if (chk_face & 0x08) printf("光センサー異常\n");        // Bit 3 (新規)
    if (chk_face & 0x04) printf("ソレノイドOK\n");         // Bit 2 (新規)
    if (chk_face & 0x02) printf("売り切れ状態\n");          // Bit 1 (新規)
    if (chk_face & 0x01) printf("FACE有効\n");             // Bit 0 (変更)
}
```

- [ ] Ver1.2 との通信を行う際は完全な書き直しが必要

### 6.3 テストケース例

```python
# SETAXON テスト (Ver1.2)
def test_setaxon_v12():
    # ダイヤル回転検知クリア
    set_face = 0x20  # Bit 5 = 1
    assert set_face & 0x20, "ダイヤルクリアビットが設定されない"

    # 複合制御: リセット + ブロック + センサーリセット
    set_face = 0x80 | 0x10 | 0x04  # Bit 7, 4, 2
    assert set_face == 0x94

# ATCKSB テスト (Ver1.2)
def test_atcksb_v12():
    # ダイヤル回転 + ドア開放 + ブロック状態
    chk_face = 0x80 | 0x40 | 0x20  # Bit 7, 6, 5
    assert chk_face == 0xE0

    # 返却ボタン押下 (Bit 4)
    chk_face = 0x10
    assert chk_face != 0x10 & 0x10  # Ver1.0 では異なる意味

# 非互換性テスト
def test_incompatibility():
    # Ver1.0 で Bit 0 = 1 は「ソレノイド ON」を意味していた
    # Ver1.2 で Bit 0 = 1 は「FACE有効」を意味する
    # 互換性なし！
    assert "Ver1.0と1.2は後方互換性がない"
```

## 7. 結論と推奨事項

### 7.1 主要な発見

1. **SETAXON**: ソレノイド制御が廃止され、ダイアル/ボタン/センサーのクリア機能が追加
2. **CHKAXON**: 変更なし（応答側 ATCKSB が大幅変更）
3. **ATCKSB**: 2機能から7機能へ拡張、かつ既存の2機能が意味が完全に変わった

### 7.2 実装上の推奨事項

| 項目 | 推奨事項 |
|------|----------|
| **後方互換性** | なし。Ver1.0 と Ver1.2 は完全に異なるプロトコル |
| **マイグレーション** | 段階的な移行が困難。完全な書き直しが必要 |
| **テスト** | Ver1.0/1.2 混在環境での互換性テストが必須 |
| **ドキュメント** | 各ビットの意味を明確に文書化する必要がある |
| **バージョン管理** | 通信パートナーの仕様バージョンを明確に把握 |
