# ATIRQ と SETAXON コマンドの仕様変更 - ver0.1 vs ver1.0

## 概要

本ドキュメントは SOMA-AXON 仕様書における **CHKIRQ応答（ATIRQ）** と **AXON基板設定コマンド（SETAXON）** の ver0.1 から ver1.0 への変更を詳細に比較したものです。

### 変更の主要ポイント

1. **ATIRQ STATUS フィールド（Byte 8-9）**：
   - **[15:8] 仕様変更**：RFU → **ダイヤル回転数カウント**（8ビット符号なし整数）
   - Bit 7 にダイヤル回転検知（Latch式）フラグを追加
   - 下位7ビット（[6:0]）の他の機能は変更なし

2. **SETAXON コマンドフォーマット**：
   - フィールド名の変更：`SET_SOL` → `SET_PRTS`
   - Bit 定義の大幅拡張：3つの新しいクリア/リセット機能を追加
   - Bit 0 の機能削除：電子マネー用ソレノイドON が RFU に変更

### 1.3 ATIRQ STATUS の主要変更点

#### 追加・変更された機能

| Bit | 機能名 | ver0.1 | ver1.0 | 状態 |
|-----|-------|--------|--------|------|
| [15:8] | ダイヤル回転数カウント | RFU | 8ビット符号なし整数（0-255） | ⚠️ **大幅変更** |
| 7 | ダイヤル回転検知（Latch式） | RFU | 0:通常, 1:回転検知 | ⚠️ **新規** |

#### 機能追加による変更内容

1. **ダイヤル回転数カウント [15:8]**
   - ver0.1：RFU（使用不可、"0"固定）
   - ver1.0：**8ビット符号なし整数（0-255）** - ダイヤル回転数を記録
   - 機能：各ATIRQ応答時に回転回数をカウント
   - クリア方法：SETAXON コマンドの Bit 5 (DIAL_CLEAR) で0にリセット可能
   - 用途：売上回転数の検証・確認、トラブルシューティング

2. **ダイヤル回転検知 Bit 7**
   - ver0.1：存在しない（Bit 7 は RFU）
   - ver1.0：新規追加、Latch式の回転検知フラグ
   - 仕様：0 = 通常状態、1 = 回転検知状態
   - 設定クリア：SETAXON コマンドの Bit 5 で可能

### 1.4 下位互換性と影響

#### 後方互換性評価

| 観点 | 評価 | 理由 |
|------|------|------|
| **既存コマンド解析** | ⚠️ **部分的影響** | [15:8] の意味が変更（RFU → ダイヤル回転数カウント）されたが、既存ビット（6:0）の意味は変わらない |
| **既存アプリケーション** | ❌ **要修正** | Bit 7 が新規追加、[15:8] の用途が変更により、ステータス解析処理の修正必須 |
| **センサー検知ロジック** | ✓ **互換性あり** | Bit 6～0 の定義は同じ（センサー操作には影響なし） |

#### 実装への影響

- **新規アプリケーション**：ダイヤル回転検知（Bit 7）とダイヤル回転数カウント（[15:8]）を処理する必要がある
- **既存 ver0.1 アプリケーション**：
  - [15:8] を RFU として無視していた場合、ダイヤル回転数カウント情報が失われる
  - Bit 7 が 1 に設定された場合の処理が未定義（修正必須）

#### 移行ガイド

```
【対応方法】

1. STATUS 解析ロジック修正：
   // ver0.1 の実装
   rfu_bits = (status >> 8) & 0xFF;  // → 0固定と想定

   // ver1.0 の実装
   dial_rotation_count = (status >> 8) & 0xFF;  // ★ ダイヤル回転数を取得
   dial_rotation_flag = (status >> 7) & 0x01;   // ★ 回転検知フラグを取得

2. ダイヤル回転数の管理：
   - SETAXON Bit 5 = 1 でカウントをリセット
   - 回転回数がオーバーフロー（256）した場合の処理を実装

3. 検証処理：
   - 売上情報のダイヤル回転数と STATUS の回転数が一致しているか確認
   - 不一致の場合はトラブルシューティング対象
```

## 3. 後方互換性評価

### 3.1 ATIRQ の後方互換性

#### 既存アプリケーションへの影響

| 観点 | 互換性 | 説明 |
|------|--------|------|
| **既存Bitの解析** | ✓ 互換 | Bit 6～0 の定義は変わらない |
| **新しいBit 7** | ⚠️ 要注意 | Ver0.1 では RFU であり常に 0、Ver1.0 で回転検知フラグ追加 |
| **[15:8]の解析** | ✓ 互換 | Ver0.1/Ver1.0 ともに RFU（"0"固定） |

**結論**：Bit 7 のみが新規追加され、他のビットは変更なし。Ver0.1 のコードは Bit 7 を無視すれば動作継続可能（**部分的な後方互換性あり**）。

### 3.2 SETAXON の後方互換性

#### 既存アプリケーションへの影響

| 観点 | 互換性 | 説明 |
|------|--------|------|
| **既存Bit（Bit 4）** | ✓ 互換 | 現金ブロック制御は同じ |
| **新しいBit（5,3,2）** | ⚠️ 要注意 | ver0.1 では RFU、設定しても効果なし |
| **削除されたBit 0** | ❌ **非互換** | ソレノイドON（ver0.1 の機能）が機能しなくなった |

**結論**：ソレノイドON 機能が削除されたため、既存のコマンド送信では**ソレノイド制御が不可能**になった。

#### 実装時の影響

```c
// Ver1.0 のコード例（非推奨）
SET_SOL = 0x01;  // Bit 0 = 1（ソレノイドON）
// ↓
// Ver1.0 では何も起こらない（ソレノイドはONしない）

// Ver1.0 の推奨コード
SET_PRTS = 0x00;  // Bit 0 は RFU に
// ダイヤル回転を検知したら自動的にOFFするはず
```

## 4. 設計上の考慮事項

### 4.1 Latch式フラグの目的

ver1.0 で追加された 3 つのクリア機能（Bit 5, 3, 2）はすべて **Latch式** のフラグをリセットします。

#### Latch式とは

- 一度イベントが発生すると、フラグが「立ったまま」になる
- SOMA 側からの指令（SET_PRTS のクリアコマンド）でのみリセット可能
- 瞬間的なイベントを検知漏らさないための設計

#### 例：ダイヤル回転検知（Latch式）

```
時間 →

[AXON] 回転検知 → Bit 7 = 1 → 状態維持 → 状態維持 → ...
                      ↑           ↓
                      └─ フラグ「立っぱなし」

[SOMA] ATIRQ受信 → Bit 7 = 1 を確認
       ↓
       SETAXON Bit 5 = 1 でクリア
       ↓
       次の ATIRQ で Bit 7 = 0
```

### 4.2 ソレノイド制御の変更理由

ver1.0 で Bit 0 が削除されたことにより、ソレノイドは「ver0.1 の指令で ON」から「自動 ON/OFF」へ変更されたと推定されます。

#### 推定される新しい動作

```
SOMA: SETAXON コマンド送信（Bit 0 は RFU）
      ↓
AXON: ダイヤル回転を検知
      ↓
AXON: 自動的にソレノイドを ON（回転許可）
      ↓
AXON: ダイヤル回転が完了したら自動的に OFF
      ↓
SOMA: ATIRQ STATUS Bit 2 を確認（ソレノイド状態）
```

**利点**：
- SOMA と AXON 間の通信タイミング依存性が減少
- ハードウェア上で自動制御が可能
- タイムアウト設定（CHK_TOUT）との連携が容易

## 6. まとめ

### 6.1 主な変更内容

#### ATIRQ

| 項目 | 変更内容 | 影響度 |
|------|---------|--------|
| STATUS [15:8] | RFU → RFU（変更なし） | ✓ 低 |
| STATUS Bit 7 | RFU → ダイヤル回転検知 | ⚠️ 中 |
| その他のビット | 変更なし | ✓ 低 |

#### SETAXON

| 項目 | 変更内容 | 影響度 |
|------|---------|--------|
| Bit 5 | RFU → ダイヤル回転検知クリア | ⚠️ 中 |
| Bit 3 | RFU → 返却ボタンリセット | ⚠️ 中 |
| Bit 2 | RFU → 光センサークリア | ⚠️ 中 |
| Bit 0 | ver0.1：ソレノイドON → RFU | ❌ **高** |
| Bit 4 | 変更なし | ✓ 低 |

### 6.2 実装優先度

1. **必須（高優先度）**
   - ver0.1 ソレノイド制御ロジック（Bit 0）の削除・置換
